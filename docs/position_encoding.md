# C01 位置编码：契合性、无采样率边界与配置

## 对当前模型的判断

当前时域Patch步长P、局部STFT步长P且填充为(W-P)/2，两路Token的名义几何中心均为 c_i=iP+(P-1)/2，因此融合后用同一时间坐标合理。实际卷积/窗函数的感受野不同，中心对齐不等于全部时频特征已经获得相同物理尺度。频域Token是“每个时间窗口的谱特征”，不是独立的频率bin序列，所以当前不强制加入二维时频RoPE。

样点RoPE适合建模样点/Token间距；绝对中心和长度特征保留窗口起点信息，有助于参数头处理时延等目标。问题在于不同未知采样率下，相同样点间距不一定对应相同物理时间。只有512/1024点长度，并不能判断采样率；本数据中长度还明显关联通信/雷达类别。

## 为什么不能直接从I/Q得到RoPE-fs

采样满足 x[n]=s(n/fs)。若令 fs'=a*fs、s'(t)=s(a*t)，则观测序列不变，所以缺少物理标定或已知生成约束时，I/Q一般不能唯一决定绝对fs。频谱轴自然表示cycles/sample，不会自行成为Hz。不能用真实参数标签反推fs后用于测试，也不能把模型估计的符号率当成已知采样率。

若有真实且全数据一致的采样率，可配置常数；有逐样本真实fs可通过模型API的sample_rates传入。若只有已知重采样比例，可研究同一记录多视图的相对时间一致性，但这不等于已解决跨记录物理标定；本次未加入重采样增强或采样率估计器。

RoPE本身参考[RoFormer作者论文](https://arxiv.org/abs/2104.09864)。RoPE-fs的动机依据用户提供的结构预训练成果介绍；这里的无fs双尺度是项目消融候选，不是该论文的原方法复现，也没有质量提升结论。

## 已实现的模式

以下设L为每条信号有效长度、Lref为固定参考长度、fref为固定参考采样率、P为Patch点数。

| model.signal.position | RoPE坐标 | 可用条件 |
|---|---|---|
| samples | c_i/P | 原样点/Token尺度；缺省模式，旧模型预测保持一致 |
| window | (c_i/P)*(Lref/L) | 归一化窗口进度；不是秒，可能削弱绝对样点跨度线索 |
| dual | 部分head用samples，另一部分用window | 无fs研究候选，保留两种距离；不保证不变性或下游提升 |
| physical | (c_i/P)*(fref/fs) | 必须提供真实fs；不能由长度猜测 |

dual默认window_head_fraction=0.5，按注意力头分配，并保留至少一个样点头和一个窗口头。参考长度固定1024，不由batch补齐长度决定。相同有效信号补齐到不同长度时，其有效Token位置保持一致。物理模式同时缩放绝对中心与时长特征，避免RoPE物理对齐后又从绝对位置旁路引入样点尺度失配。

固定64点STFT的物理窗宽为64/fs，全局FFT频率轴也依赖fs。真实跨采样率适配仍可能需要物理窗宽或可验证的重采样方案；只改RoPE不能宣称整个前端已经跨采样率对齐。

## 配置与使用

在预训练和适配配置的model.signal里，已有如下选项：

```json
"position": "samples",
"position_options": {
  "reference_length": 1024,
  "window_head_fraction": 0.5,
  "absolute_features": true,
  "sample_rate_hz": 0.0,
  "reference_sample_rate_hz": 1.0
}
```

新实验如需研究双尺度，只需两阶段均改position为dual，保持absolute_features=true，以保留参数任务起点/长度线索。原子原始I/Q词表不依赖位置编码，可在同划分下复用以隔离位置变量；教师特征构建的第二轮词表依赖教师编码器，不能假装是另一位置模式生成的词表。

sample_rate_hz=0表示未知，physical模式会拒绝运行。只有掌握真实常数fs时才填入；reference_sample_rate_hz是选择坐标单位用的固定参考，并不是估计值。多采样率数据不能用一个虚构常数覆盖；直接模型API支持传入[B]形状的正有限sample_rates，当前C01 CLI没有逐记录fs字段。

所有正式配置当前仍保持samples，避免改变已运行模型。修改文件不会修改正在运行的进程。切换模式会改变前向行为，不能严格resume；应建立新实验。新预训练与任务适配的position/options必须一致，代码会检查初始化语义。模型宽度、层数等也必须匹配；本次没有替用户改动这些架构选择。

## 验证范围

新增检查覆盖旧samples前向逐项一致、双尺度两类间距、补齐不变、真实fs相对时间间距与绝对时长一致、未知/NaN/非正fs拒绝、掩码不泄漏、梯度有限和模型配置往返。额外用CPU双进程短测dual结构预训练、全参数适配、导出和官方样例推理，避免占用用户正在训练的GPU。

这些是数学语义和执行性验证，不证明dual优于samples，也不证明C01的真实跨采样率泛化。研究比较应保持结构词表、更新预算、任务适配配方一致，并报告两分类Accuracy/F1及七参数误差。
