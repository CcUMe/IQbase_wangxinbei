# 单卡、双卡兼容性检查（2026-11-12）

训练和统一推理入口均支持单卡或双卡。构词表与独立评估保持单进程，导出使用CPU。已核对code/configs下16份配置，其中11份训练配置；没有修改历史运行目录内的实际配置或既有权重。

## 启动设置

在训练或推理配置的runtime分组配套设置：

```json
"gpus": "2",
"processes": 1
```

双卡改为：

```json
"gpus": "2,3",
"processes": 2
```

双卡只接受0,1、2,3或4,5。入口自动启动torchrun，命令仍只传--config。一个进程配置两个GPU编号会报错，避免以为两卡均已使用。显式外部torchrun仍负责自己的设备安排。内部使用可见设备的局部编号；NCCL初始化显式指定对应device_id。

训练data.batch_size为每卡每个微批次的记录数，有效batch为其乘以进程数和gradient_accumulation_steps。推理batching.batch_size为Parquet读取块大小，随后分给各进程，并非训练的每卡batch语义。

## 修复内容

- 监督损失先同步各任务/参数的有效标签数，再按全局有效数归一化。某张卡没有该任务标签时也参加必要的同步与图连接，避免局部均值直接平均造成任务梯度权重偏移。
- 非活动头保护按梯度累积窗口收集活动任务，并跨卡合并。没有有效目标的头恢复grad=None，防止AdamW动量和衰减继续更新它。所有随附训练配置开启该保护，生产训练入口拒绝关闭；历史诊断记录保持原样。
- 所有随附训练配置显式开启QK归一化，保留旧检查点配置缺省语义。分阶段冻结/解冻保留优化器分组与正确的DDP重建逻辑。
- 推理使用eval和inference_mode，不反向传播。双卡使用相同单模型，各自预测不同记录，rank 0按原始行序合并；内部排序字段不进入竞赛输出。合并失败不会替换已有结果文件。

训练终端与进度日志仍为rank 0统计；在监督标签分布不均时，其loss是用于DDP的缩放后局部贡献，不能解读为已经聚合的全卡平均loss。验证入口的指标口径没有因此改变。

## 断点与初始化

严格resume要求进程数、batch、词表、模型与训练配方一致。切换单/双卡重新开展实验时，使用warmstart重新建立优化器；更新词表或从预训练进入下游适配时，使用init_checkpoint，仅加载共享基座。不同语义的词表即使大小相同，也不能复用旧预测头和优化器。

本轮没有改变用户已选的GPU、模型尺寸或实验输出路径；修改配置只影响之后启动的进程。旧模板的保护开关已更新，若复现旧运行应读取该运行的resolved_config.json，而不是假定当前模板仍等同于旧配方。
