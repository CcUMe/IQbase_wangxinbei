# 原金字塔共享相位关系适配

本版按数据标签正确进行模型优化。使用原21M金字塔作为基座，新增一个轻量共享适配器，让多间隔相位关系在编码过程中可被利用；没有引入第二个分类基座。正式训练入口只有一份：`code/configs/supervised/pyramid_phase.json5`。

## 为什么这样改

独立探针显示，多间隔相位谐波和相位曲率有判别作用，但手工特征分类器仍弱于现有基座，在共同难例上的新增纠错也不明确。因此本版不把210维统计直接拼到分类头，也不假定它们可以替代原编码。

改为保留局部关系随时间的变化，让原Transformer和局部编码块学习如何使用。它是有依据的架构候选，探针结果不是正式准确率增益的证明。

## 共享结构与对齐

```text
原始I/Q → 原RMS归一化 ──→ 原时频前端 → P16 token ──＋─→ 原8层Transformer
                 │                              ↑
                 ├→ 原复数前端 → P8 token ───────＋─→ 原局部块＋Transformer
                 │                              ↑
                 ├→ 原复数前端 → P4 token ───────＋─→ 原局部块＋Transformer
                 │                              ↑
                 └→ 一次局部相位关系提取 → 64维共享编码 → 各尺度窗口mean/std与投影

三个尺度 → 原末端时频／跨尺度交互 → 原调制头、协议头、七参数读出
```

新增的多间隔关系只计算一次；图中的三个投影负责尺寸与窗口对齐，不是三个编码器。原前端的lag=1特征保留。所有新增参数都注册在`backbone.pyramid.phase_relations`下，由三任务共同使用。

| 路径 | 对齐窗口 kernel/stride/padding | 注入位置 | 1024点token数/宽度 |
|---|---|---|---|
| P16 | 16/16/0 | 时频、能量与位置回注之后，第1层Transformer之前 | 64/384 |
| P8 | 16/8/4 | 分支Patch嵌入与归一化之后，第1个局部块之前 | 128/192 |
| P4 | 8/4/2 | 分支Patch嵌入与归一化之后，第1个局部块之前 | 256/192 |

512点对应32/64/128个有效token。窗口与原分支相同，窗口边缘按有效点数计算矩；每层清理padding。真实的零值样点仍然有效，只有length定义的padding被排除。

新增特征在实值token空间注入，不把相位不变的特征直接相加到仍按复数通道约定处理的原始复数stem里，避免混淆两种变换语义。

## 相位关系的含义

对RMS归一化复信号`z[n]`，计算单位化的`z[n]·conj(z[n-lag])`，显式提供其实部、虚部及1/2/4阶谐波。默认lag为1、2、4、8、16、32、64，均是原样点间隔，不推断符号周期或采样率。

相位曲率使用相邻样点的相位增量，在相隔lag后再次做共轭乘积，描述相位变化本身如何变化，提供1/2阶分量。恒定频偏在这类曲率视图中抵消，但保留在原I/Q与相位增量视图中；没有对输入强制去频偏。

每个lag有12个分量：6个相位谐波、4个曲率分量、2个幅度／历史权重，共84个输入通道，经64维点卷积、轻量深度卷积和点卷积编码。幅度软权重只用于抑制零幅或极小幅乘积的数值不稳定，不是SNR估计，不把低绝对RMS记录当噪声丢弃。

该局部视图没有再减去整条记录的均值，保留原接收I/Q定义。它不逐字复现离线探针，而是据其线索构造可学习的局部表示。

## 为什么不会一开始破坏旧表征

三个尺度的最终投影均零初始化。固定随机种子时，新增模块使用独立RNG作用域，原有编码器和任务头初始化不变；加载原21M权重后，在推理模式下检查FP32和BF16，初始三任务输出均与旧模型逐位一致。训练时Dropout仍正常随机采样。

每个尺度的修正为：

`原token + max_scale × sigmoid(gain_logit) × tanh(投影特征)`

可学习增益初值0.1，上限0.25，修正每维也受此上限约束。Dropout放在投影前，因此训练时也保持输出界限。第一步先训练零初始化投影；后续更新相位编码器自然获得梯度，不设gradual冻结阶段。

这是数值与起步兼容保证，不能保证训练后的协议／参数精度绝对不变。它们仍须由完整验证监控。

## 参数、训练与竞赛约束

- 最终参数21,074,233；新增108,227，约为原模型的0.52%。
- 共享参数19,261,795，占91.40%；单模型满足现有小于1B、共享权重大于80%的检查。
- 输出仍为23类调制、8类协议、7个参数；原始RMS能量、频谱、长度与绝对位置通路均保留。
- 默认从零监督、单卡GPU 1、batch256、累积1；沿用3e-4 AdamW、500步warmup、40轮cosine、最低LR比例0.05及原三任务损失。
- 本候选关闭mid_fusion、modulation_temporal、hierarchy、hybrid，避免把多项未经验证的改动叠加。
- 原始数据缓存及划分不变，不按真实类别选择预处理或分支，不删除困难记录。
- 当前适配原金字塔的监督训练／推理；与原金字塔一样，结构预训练入口尚未接入，不将监督测试当作预训练兼容性证明。

## 启动

在项目根目录激活py313环境后：

```bash
python code/training/train.py --config code/configs/supervised/pyramid_phase.json5
```

日志位于`logs/supervised_pyramid_phase/<上海时区时间戳>/`，包括可读日志、逐epoch进度、完整验证指标和TensorBoard。

```bash
tensorboard --logdir logs/supervised_pyramid_phase --port 6006
```

新增可调参数全部集中在`model.phase_relations`并逐项注释。第一次运行建议沿用默认设置，先看前14类、逐类F1与其他任务完整指标，再决定改lag、宽度或增益。

## 旧权重、续训与导出

原`pyramid_v1_171823.json5`仍可运行、加载旧权重并按旧配方续训。新结构不能用`--resume`接旧结构的优化器／调度。

技术上支持把原21M同结构权重完整热启动到本版：`--warmstart-checkpoint logs/supervised_main/20261112_171823_031143/best.pt`。只允许新增适配器参数缺失，原参数必须匹配，新增投影重置为零；重新构建优化器与调度。这是另一种初始化实验，不能与从零等预算训练混为一谈。默认配置不启用它；不同结构的96M权重不能通过此接口直接加载。

已训练本版的checkpoint要求lag、谐波阶数等语义一致才能热启动，即使张量形状相同也不能重解释。新运行的严格续训使用本版配置和该运行自己的last.pt。

导出与推理复用原入口：

```bash
python code/training/export.py --checkpoint logs/supervised_pyramid_phase/<运行时间戳>/best.pt --output weights/pyramid_phase
python code/infer.py --weights weights/pyramid_phase --input /path/to/input.parquet --output /path/to/predictions.jsonl --gpus 1
```
