# IQFormer取舍复核

核验日期：2026-11-12，Asia/Shanghai。本次为源码及架构判断复核，不改变当前监督模型实现或训练入口。

最新约束与实施：用户随后明确要求保留原主干、两者结合，当前已切换为原时频Transformer＋共享阶段式细节支路的组合基座。20.97M参数、共享92.14%，从零监督；下文中12.42M直接替换版属于中间实现。当前方式以[运行指南](../supervised_multiresolution.md)为准。

后续实施：用户要求相应改进后，已实现code/models/hierarchical.py，并将supervised/main.json5切换为高分辨率时频融合、两层BiLSTM、三阶段局部/全局编码。当前12.42M参数、共享86.41%；具体启动与支持范围见[监督模型指南](../supervised_multiresolution.md)。下文关于旁路结构的分析描述的是此次重构前的状态。

## 结论

用户提供的分析指出了上一版决策中的真实问题：在“先确定架构、从零监督验证”的目标下，旧预训练权重兼容性不应主导架构选择。现有C01实验没有证明IQFormer的BiLSTM、I通道STFT或完整阶段式编码不适用，也没有证明当前多尺度旁路优于IQFormer。

但不能直接接受“官方IQFormer默认逐阶段下采样、扩大通道”的具体描述。公开代码具备该构造能力，作者main.py所选配置却没有启用它。相应的设计建议需要与原始事实分开。

## 已核验的作者代码

- [主入口main.py](https://github.com/WestdoorSad/IQFormer/blob/main/main.py)：导入model.IQFormer；2016数据使用layers=[2,3,2]，其他分支使用[3,3,3]；两者均为embed_dims=[64,64,64]。
- [模型IQFormer.py](https://github.com/WestdoorSad/IQFormer/blob/main/model/IQFormer.py)：I/Q stem的时间stride为1；STFT stem仅压缩频率维；融合后进入两层BiLSTM；随后进入各阶段。仅当相邻embed_dims不相等时插入下采样Embedding。
- [实际使用的dataset/dataset.py](https://github.com/WestdoorSad/IQFormer/blob/main/dataset/dataset.py)：对I通道执行scipy.signal.stft，window=blackman、nperseg=31、noverlap=30、nfft=128，截取前32个频率bin后转torch.Tensor。根目录dataset.py不是本次核验到的有效路径。

本次通过连接的GitHub工具重读了这些原始文件，而非仅依据第三方介绍。作者仓库现有模型源码与此前本地核验快照的关键结构一致。

## 1. 阶段式结构：应采纳的核心与需要纠正的描述

公开实现中的Stage将ConvEncoder与末尾的IQFormer_Encoder组合；后者包含局部卷积、Efficient Additive Attention和前馈模块。这是一种局部/全局混合编码方式，不是简单堆叠标准二次复杂度自注意力。

模型构造器确实提供阶段间下采样，但触发条件是相邻embed_dims不同。main.py均选择[64,64,64]，故该默认网络不会插入这些下采样模块；down_stride参数出现在调用中也不等于模块实际被建立。

因此，直接得到的研究依据是“在较高时间分辨率上组织局部和全局关系”。“逐步下采样并扩展通道”可以作为C01的工程适配，但不能说成已经忠实采用作者默认配方，更不能仅用此代码作为该策略必然提高C01性能的证据。

当前C01实现的区别：旧主干在P16后做8层编码；另有stride8/4两个轻分支，时频交互位于其局部/Transformer编码之后，末端做跨尺度摘要融合。它保留了更细token，但没有复现“高分辨率融合→循环整合→阶段编码”的整体过程。

## 2. BiLSTM：位置值得重视，但“必需”未经证明

作者BiLSTM是2层、双向、batch_first；默认首阶段D64时input_size=32、每方向hidden_size=32、输出64维。输入stem和融合不做时间下采样，故1024点输入时处理长度1024的序列，不是64token或先压到256token再处理。

这使“压缩前先整合连续时序关系”成为合理借鉴。当前模型存在局部卷积及注意力上下文建模，不能说它完全没有相关能力；同样没有证据证明这些模块与该位置的BiLSTM等价，或BiLSTM一定带来增益。

成本结论应基于具体通道数、序列长度和设备实测。C01还包含512点雷达与时延等参数任务，双向序列处理需按真实有效长度处理；仅在末端mask输出不足以阻止反向LSTM从padding读入额外状态。原始任务是完整窗口推理，双向建模本身不违反因果约束或竞赛接口。

## 3. I通道STFT：需要明确表示定义

I通道频谱与复I/Q功率谱没有简单的完整信息包含关系。当前表示为复I/Q局部log功率谱，保留正负频率谱形，但不保留局部STFT相位。作者数据代码中的I通道STFT又是另一种表示，不能只依据“用了两个输入通道”认定前者对分类更好。

另外，作者将complex STFT数组直接传torch.Tensor，没有显式abs、power或log。已在当前Python环境做独立小检查（没有执行作者训练代码）：1024点float32输入得到32×1024个STFT系数；转Tensor后为float32，与STFT实部相等，并出现丢弃虚部的警告。这是当前环境下对公开数据代码行为的核验，不是对作者历史环境或论文实验有效性的完整复现。

因此，后续实现需明确选择实/虚、幅度还是功率谱；若选择幅度或log功率，应标为C01适配。不能把“使用I通道STFT”写成已精确复现作者输入。对频移等任务，保留复I/Q及其频谱通路是合理的信息保留选择，但收益仍需任务指标验收。

## 4. 对下一步架构的修正建议

若继续重构，应将IQFormer式“高分辨率时频融合→轻量BiLSTM→局部/全局阶段编码”作为主干组织方式的重要起点；多尺度读出沿用MST思路，七参数查询和独立字段读出继续保留。需要压缩序列时，在较充分的高分辨率建模后进行，并明确这是本项目的适配设计。

不建议在当前P16主干后再简单添加BiLSTM并宣称采纳了上述思想：其处理位置和信息粒度与作者不同。也不宜为了使用所有论文组件再保留一个大旧主干与一个完整新主干并列；当前无旧权重兼容需求，可以围绕一个共享阶段式编码器设计。

这项修正不会自动违反竞赛约束：共享的阶段式编码器、BiLSTM和时频分支可以供三任务共同使用，最终一个checkpoint、轻量三任务头。仍需实际统计参数≤1B、共享>80%，核验23/8/7输出、原单位参数与统一无标签推理；国产平台上的循环算子性能则要实际验收。

当前判断是设计优先级修正，不是已证明新主干更强。上一轮60项CPU检查证明现有代码可以运行及接口正确，没有证明架构优于IQFormer或调制准确率已经改善。
