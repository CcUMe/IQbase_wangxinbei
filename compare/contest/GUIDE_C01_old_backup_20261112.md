## 1. 赛题要点

### 1.1 任务与数据

| 项 | 内容 |
|---|---|
| 输入 | IQ 双通道序列，长度 512 或 1024 点 |
| 任务 A | 信号体制识别，8 类（WiFi、Bluetooth、5G、Radar 等），字符串标签 |
| 任务 B | 调制/波形识别，23 类（OOK、BPSK、16QAM、LFM、Barker Code 等），字符串标签 |
| 任务 C | 物理域参数估计，7 个参数（码元速率、带宽、脉冲宽度等），连续或计数数值 |
| 规模 | 训练数据合计约 120 万条 |
| 格式 | Apache Parquet，逐样本一行：`task`（测试项类型）、`sample_id`、`iq`；训练集另有标签和"有效性标识"字段；测试集只有输入字段 |

每条样本带一个 `task` 字段，即**每条样本很可能只属于一个任务、只有该任务的标签**【待确认】。

**已确认的接口（来自官方样例）：**

- 输入 Parquet 每条记录：`task`（取值 `"modulation"`、`"protocol"`、`"parameter"`）、`sample_id`（如 `"sample_000001"`）、`iq`（形如 `[[I0,Q0],[I1,Q1],…]`，即 L×2 的浮点序列，注意是"时间在前、IQ 在后"）。
- 输出 JSONL，每行对应一条输入，三个字段 `task`、`sample_id`、`prediction`：
  - 调制/体制任务：`prediction` 是类别字符串，如 `"BPSK"`、`"WiFi"`。
  - 参数任务：`prediction` 是含 7 个键的对象：`symbol_rate`、`bandwidth`、`frequency_shift`、`pulse_width`、`pri`、`time_delay`、`number_of_pulses`。
- 参数预测必须用**数据规定的原始单位**，**每条样本 7 个键都要输出**，不输出有效性掩码。主办方按自己保存的有效性标记，只对适用的参数评分。
- 样例数值显示量纲跨度极大（码元速率约 1e3，脉宽约 1e-6），输出时必须保留足够有效数字（见第 8 节自检清单）。

### 1.2 硬约束（红线）

1. 模型参数量 < 1B。
2. 不同任务之间**共用基座权重 > 80%**。
3. 不得为不同任务分别训练多个基座模型。
4. 不得做多个小模型集成。
5. 不得外挂知识库增强。
6. Docker 镜像为 Linux 架构，预装推理所需全部依赖，不得声明匿名 VOLUME，不得运行时下载。
7. 文件 UTF-8 编码；目录和文件名只用英文、数字、下划线。
8. 运行环境基线：Ubuntu 22.04 LTS、CUDA 12.x、PyTorch。

### 1.3 评分

**初赛**（纯精度）：体制 30 + 调制 30 + 参数估计 40。

- 分类任务：`S = 100 × 准确率`（准确率相同时比宏平均召回率）。
- 参数估计：`S = 100 × 1 / (1 + RMSE / 固定参考尺度)`。

**复赛**：自动评分 70% + 专家评审 30%。

- 自动评分：体制 20 + 调制 20 + 参数估计 30 + **计算效率 30**。
- 效率分 `S4 = 100 × (N − Rt) / (N − 1)`，`Rt` 是推理时延**排名**，`N` 是复赛队伍数。
- 专家评审（满分 100）：技术路线 15、技术创新性 20、模型能力 20（按线下复现情况和计算效率提升程度评比）、**工程实现 30**（可行性、能否落地、是否预判风险并制定应对措施）、成果应用价值 15。工程实现分值最高，技术报告里要有独立的"风险与应对措施"章节。

### 1.4 数据实测结论（来自 `eda_report.txt`，训练集全量标签统计 + 约 1.8 万条信号抽样）

以下是实测事实。本文其他章节与这里冲突时，以这里为准。

**规模与结构**

- 训练集共 1,179,000 条，三个 Parquet 文件，每个行组 1024 行。`iq` 在训练集里是 `list<list<float>>`，在官方样例输入里是 `list<fixed_size_list<float>[2]>`，**读取代码必须两种都支持**。形状都是 [L, 2]。
- 每条样本只属于一个任务，只有该任务的标签：

| 任务 | 样本数 | 占比 | 类别分布 |
|---|---|---|---|
| parameter | 828,000 | 70.2% | 见下 |
| modulation | 207,000 | 17.6% | 23 类，每类恰好 9,000 条 |
| protocol | 144,000 | 12.2% | 8 类，每类恰好 18,000 条 |

- 文件按任务排序（part_001 是调制加体制，part_002、part_003 几乎全是参数），**必须全局打乱**，验证集必须随机分层抽取。
- `sample_id` 是 32 位随机十六进制串，全局唯一，不含信息。这里的抽样检查没有发现重复信号，但队长的全量审计发现了 13,129 组跨任务重复波形，以 1.6 节为准。
- 类别字符串以 `task_schema.json` 为准，注意带斜杠、空格和下划线的写法：`Radar/Coherent Pulse Train`、`Radar/Barker Code`、`Radar/Polyphase Barker Code`、`Radar/Frank Code`、`Radar/LFM`、`pi_4DQPSK`、`FM broadcast`、`Idle background`。

**参数任务是两个互不重叠的子群，各占一半**

| | 脉冲组（414,000 条） | 通信组（414,000 条） |
|---|---|---|
| 序列长度（抽样） | 全部 512 | 全部 1024 |
| 有效参数 | `pulse_width`、`pri`、`time_delay`、`number_of_pulses` | `symbol_rate`、`bandwidth`、`frequency_shift` |
| 无效参数的标签值 | 0 | 0 |

有效性只有这两种组合，不存在其他模式。

- **通信组的三个参数全是离散档位**：
  - `symbol_rate` 6 档：62.5、100、300、500、1000、2000。
  - `bandwidth` 21 档：65 到 3500。它与 `symbol_rate` 的计数高度吻合（例如 62.5 与 2000 都是 83,170 条，2000 与 2550 都是 27,631 条），很可能两者由同一个隐含信号类型联合决定，请用交叉表核实。
  - `frequency_shift` 13 档：−50 到 50 步进 10（每档约 1.5 万条）、100（约 14.8 万条）、1000（约 10 万条）。
- **脉冲组**：
  - `pulse_width` 连续，10–16 µs；`pri` 连续，17–23 µs；`time_delay` 连续，1–10 µs；三者近似均匀分布。
  - `number_of_pulses` 取 2、3、4、5、6，近似均匀。
  - 由标签与包络实测量之比推断采样间隔约 0.30–0.31 µs（即脉宽约 32–51 个采样点，PRI 约 54–74 点，时延约 3–32 点）。这与公开数据集 RadChar 的设定（512 点、3.2 MHz 即 0.3125 µs、参数范围完全相同）吻合，见 4.11 节；`eda2_c01.py` 会给出拟合结果以最终确认。
  - 通信组的采样率没能从数据直接推断出来。文献线索指向 20 MHz（EMind 论文中的 EM-Comm 数据集），若成立，则 `symbol_rate`、`bandwidth`、`frequency_shift` 的单位很可能是 kHz。同样待 `eda2_c01.py` 的结果确认。
- 官方样例的期望输出里，无效参数填的是 `0.0`。

**长度与类别强相关**

- 调制任务：5 个 `Radar/*` 类全部是 512 点，其余 18 类全部是 1024 点。
- 体制任务：只有 `Radar` 有 512 点（约一半），其余 7 类全部 1024 点。

**信号来源明显分两种**

- 一种幅度很小（RMS 约 1e-3）、数值是 1/32768 的整数倍、严重过采样（90% 功率集中在约 5% 的频点内）。调制任务中的 OOK、BPSK、QPSK、8PSK、OQPSK、AQPSK、各阶 QAM、2FSK、4FSK、MSK 共 14 类属于这种，参数任务的通信组看起来也是这种。
- 另一种幅度在 1 左右、占满大部分带宽：CSS、FM、GFSK、pi_4DQPSK、5 个雷达类，以及体制任务的大部分类别。

**由此产生的设计修订**

1. **参数头改为以分类为主**（详见 4.8 节参数头定义）：`symbol_rate`、`bandwidth`、`frequency_shift`、`number_of_pulses` 做分类，只有 `pulse_width`、`pri`、`time_delay` 做回归。
2. **高分辨率频谱支路升为主线**：窄带那 14 类调制只占 64 点 STFT 的两三个频点，分辨率不够。增加一路 N=256、hop=16 的 ConvSTFT，输出 (B, 256, L/16)，经卷积映射后在阶段 3（L/16）并入频域流。
3. **调制任务的难点是 14 个窄带类**（尤其高阶 QAM 之间）。它每类只有 9,000 条，是三个任务里数据最少的；而参数任务通信组有 41.4 万条同源信号。共享主干让调制任务间接用上这批数据，这是"任务间协同增效"的实际来源，用消融 A6 量化。
4. **任务均衡采样**：参数任务占 70% 的样本，但两个分类任务占初赛 60% 的分数。每个 batch 按固定比例从三个任务取样（起点 1:1:2，调制:体制:参数），不要按自然比例。
5. **RMS 归一化必不可少**（幅度跨 3 个数量级），同时保留 `log(rms)` 作为特征。
6. **长度可以作为特征**：加一个 2 项的长度嵌入加到池化后的表征上。它在训练集里与类别强相关，测试集若不保持这一规律会有风险，汇报时注明。
7. **验证集比例**：调制、体制任务各取 10%（每类 900 / 1800 条），参数任务取 5%。

### 1.5 第二轮数据核实结论（来自 `eda2_report.txt`）

**全量确认的事实**

- 长度与子群、类别的对应关系在全量数据上无一例外：脉冲组 414,000 条全部 512 点，通信组 414,000 条全部 1024 点；调制任务 5 个雷达类各 9,000 条全部 512 点，其余 18 类全部 1024 点；体制任务只有 `Radar` 有 512 点（9,030 条 512 点，8,970 条 1024 点）。
- Arrow 零拷贝展平读取 IQ 的快速路径在训练集上可用（`col.flatten().flatten().to_numpy()` 加 `list_value_length`），推理读取就用这种写法。

**通信组：采样率 20 MHz，三个参数的单位是 kHz**

- 证据：`frequency_shift`=100 的样本载频估计中位数为 0.0050 周期/采样点，1000 的为 0.0485，换算采样率约 2.0e4；`symbol_rate`=1000 的样本包络平方谱线集中在第 51 个频点，换算约 1.99e4。单位按 kHz 解释时采样率为 20 MHz，与文献线索一致。
- `frequency_shift` 是**载频偏移**，不是 FSK 频偏。
- (`symbol_rate`, `bandwidth`) 只有 22 种组合，三元组合共 75 种。`bandwidth / symbol_rate` 只取 8 个值：0.65、0.675、1.0、1.275、1.5、2.5、3.5、32。
- 通信组内部又分两种来源：
  - **实采窄带**（RMS 约 1e-3，约 24.8 万条）：`frequency_shift` 只取 100 或 1000，这两档靠载频估计可以轻松分开。`symbol_rate` 取 100/300/500/1000，对应每个码元 200/67/40/20 个采样点，**1024 点里只有约 5 到 51 个码元**。同一 `symbol_rate` 下的不同带宽（如 65 与 67.5、650 与 675）在频谱上相差不到一个频点，很可能由调制方式决定，而不是能从谱宽直接量出来的量。
  - **仿真宽带**（RMS 约 1.7，约 16.6 万条）：只有 4 种 (`symbol_rate`, `bandwidth`) 组合：(62.5, 2000)、(1000, 1000)、(1000, 1500)、(2000, 2550)。`frequency_shift` 取 −50 到 50 步进 10。10 kHz 只有半个频点，而同一档内单样本载频估计的四分位距约为档间距的十几倍，**这 11 档基本无法逐档分辨**，只能估出一个带较大误差的连续值。

**脉冲组：采样间隔约 0.311 µs，一半样本信噪比很低**

- 用高信噪比样本的脉冲沿拟合：`pri` = 3.103e-7 × 上升沿间距（R²=0.994），`time_delay` = 3.113e-7 × 首个上升沿位置（R²=0.996，截距约为 0）。即采样间隔约 0.311 µs，与 RadChar 的 3.2 MHz（0.3125 µs）相差约 0.5%，在这种粗测量的误差范围内。
- 参数定义得到确认：`time_delay` 是首个脉冲起点相对窗口起点的时间，`pri` 是相邻脉冲起点的间隔，最后一个脉冲最晚在约第 450 个采样点结束。
- 四个参数两两不相关，各自均匀分布。
- **约一半样本的脉冲在包络上已经看不出来**（包络信噪比中位数 8.4 dB；简单阈值检测只在 36.6% 的样本上数对了脉冲个数）。这部分样本的误差决定了三个回归参数的 RMSE，模型必须靠长时间非相干积累才能从中提取信息。

**调制任务**

- 14 个窄带类的信噪比很高（谱信噪比 25–52 dB），各类的粗粒度谱特征几乎一样，而且带有 100 或 1000 kHz 的载频偏移和不同的码元速率（与参数任务通信组的实采窄带部分同源）。码元数很少，高阶 QAM 之间可用信息有限，**这部分存在信息量上限，不是模型容量问题**。
- 其余 9 类（CSS、FM、GFSK、pi_4DQPSK、5 个雷达类）是仿真信号，信噪比低且范围宽（谱信噪比 5–37 dB），失分主要来自低信噪比样本。

### 1.6 队长已有工作（`leader/` 目录）：可用结论、基线数字与取舍

`leader/` 是队长截至 2026-11-11 的代码和文档快照。本节依据其中的阶段复盘（`docs/C01_model_and_validation_review_20261111.md`）、数据核验（`C01_数据核验与路线修订.md`）、模型源码（`code/models/rf_model.py`）和推理入口（`code/infer.py`）整理；其余文档只做了关键词检索，`lecture/` 下的讲座解析没有细读。**这些是有实测支撑的本队结果，优先级高于本文前面的推断；但不要照抄其结构，分歧点见本节末尾。**

**（一）工作方式：自研模型独立搭建，与队长的线并行；只保证两边的数字可比**

队长的模型由队长自己推进。本文的自研模型（第 4 节）是另一条线，有自己的代码目录、训练脚本和推理入口。`leader/` 只读，用途有三：数据结论和坑（本节二、四）、可对照的基线数字（本节三）、可以借鉴的具体实现（例如按长度分桶的组批、非活动头保护、输出校验）。需要哪段实现就自己重写或移植单个函数，不要整体依赖队长的工程。

**唯一必须与队长保持一致的是数据划分和评分口径**，否则两个模型的分数无法比较。按下面的规则在自己的代码里复现：

- 内容哈希：`blake2b(struct.pack('<I', 长度) + iq.astype('<f4').tobytes(), digest_size=16)`，`iq` 形状为 [长度, 2]。
- 划分：`salt = int.from_bytes(blake2b(b'2026', digest_size=8).digest(), 'little')`；取哈希前 8 字节按小端转成整数，与 `salt` 异或后小于 `0.1 × 2^64` 的进验证集，其余进训练集。同一哈希的记录自然落在同一侧。
- 先把 6 条官方接口样例对应的哈希整体剔除。
- 复现后核对行数：训练 1,060,812，验证 118,182。对不上就说明哈希或划分实现有出入，先解决再训练。实现见 `leader/code/training/prepare_data.py` 第 46–56 行和 `leader/code/utils/audit_c01_dataset.py`。
- 本地代理分（`leader/code/utils/engine.py` 第 216–220 行）：`参数分 = 1 / (1 + 七个字段的 RMSE_j / std_j 的平均)`，`std_j` 是训练侧该字段有效标签的标准差，RMSE 只在有效标签上算；`代理分 = 30 × 体制准确率 + 30 × 调制准确率 + 40 × 参数分`。它不是官方分数，只用于两条线之间对比。

**（二）必须采纳的数据处理结论**（本文之前遗漏或说错的地方）

- **存在 13,129 组跨任务的完全重复波形**（调制+参数 10,851 组，体制+参数 2,080 组，调制+体制 151 组，三者都有 47 组），同任务内没有重复。本文 1.4 节"抽样内未发现重复"是抽样规模太小造成的误判。**训练/验证划分必须按波形内容哈希分组**，同组记录只能在同一侧，否则存在跨任务泄漏。队长已实现。
- 这些重复组同时也是资源：同一波形带有两个任务的真实标签（见下文 P0 诊断）。
- 官方 6 条接口样例全部能在训练集里找到逐元素相同的波形，只能用于接口测试，需从训练和验证中隔离。
- **PyArrow 19.0.0 读官方样例会报错，25.0.0 正常。** 提交环境必须锁定实测可用的版本。
- 有效的 `frequency_shift` 中有 15,131 个真零，判断是否有效只能看 `*_valid`，不能看数值是否为零。分类记录的参数列是空值，参数记录中不适用的字段是 0，两种情况都要处理。
- 队长的划分是按内容哈希阈值的近似 90/10：训练 1,060,812 条，验证 118,182 条。

**（三）基线数字**（队长本地验证集，非官方成绩；代理分用训练侧尺度代替未公布的参考尺度）

**（四）已有实验结论（不要重复做，除非改变了条件）**

- **加大模型几乎没用**：95.7M 相对 17.1M，调制只高约 0.5–2.5 个百分点（取决于是否重训读出头），体制持平，而且大模型训练准确率接近 100%、验证约 64%，严重过拟合。冻结基座重训线性头和 MLP 头结果相同，瓶颈在共享特征的泛化。**这是"复赛用小模型"最直接的依据。**
- **联合训练优于单任务**：17M 模型在相同调制曝光下，联合训练的调制准确率比只训调制高 2.33 个百分点（单种子）。这是"任务协同增效"的现成证据，对应消融 A6。
- 已试且未见稳定收益：整窗相位旋转与循环平移增强、标签平滑、监督对比损失、局部残差卷积前端、给旧权重直接加融合归一化、统计量读出（仅 +0.27 个百分点）。这些是单种子、有限预算下的结果。
- **两个必须保留的稳定性修复**：
  - 注意力的 Q/K 做逐头单位 RMS 归一化。不加时大模型注意力 logit 达到数万到十几万，注意力退化成单点。
  - 一个 batch 里没有标签的任务头，在优化器更新前把梯度置为 None。否则 AdamW 的动量和权重衰减会改动这些没有参与计算的头。任何"每个 batch 只含部分任务"的训练方式都要处理这一点。
- 训练组织方式：每个 batch 是同一任务、同一长度的记录，任务间均衡轮转。

**（六）与队长方案的分歧（不照抄的部分）**

1. **时间分辨率**。队长的时域流只有一层核为 5 的卷积，随后直接做 16 点分块，512 点只剩 32 个 token，每个 token 跨约 5 µs。而脉宽、PRI、时延的取值范围只有 6–9 µs。队长三个脉冲时间参数的 MAE 为 0.38–0.57 µs；EMind 论文在 RadChar 上报告的全信噪比 MAE 为 0.22–0.32 µs（数据划分不同，只能作量级参考）。这提示脉冲参数还有明显提升空间，本文的"多级卷积逐步下采样到 16 倍"前端应作为第一优先的结构实验。队长试过的"局部残差前端"是在分块前加一层同分辨率卷积，与这里的多级下采样不是一回事。
2. **提交用的模型规模**。队长当前的默认推理权重是 96M 的大模型。按（四）的结论和复赛时延权重，提交主线应回到小模型，并继续向下探索更小的规模。
3. **推理读数方式**。队长的 `infer.py` 用 `to_pylist()` 逐条转换 IQ、默认 batch 128。这在功能上正确，但速度很慢；复赛前要改成 Arrow 零拷贝展平加大 batch（见 1.5 节）。
4. **算子**。队长默认用 `torch.fft` 算全局谱（另有矩阵乘替代路径）、`einsum`、旋转位置编码里的 `cos/sin`。国产平台导出时默认应切到可移植路径，并用固定权重实现。
5. **验证集被反复用于选型**。队长自己也指出了这一点。需要从训练侧再切出一份锁定的确认集，只在里程碑节点评一次。
6. **预训练上的投入**。结构化预训练的机制复杂，目前没有下游证据。在 P0、P1 实验做完之前，不建议继续在它上面投入训练时间。

**（八）自研模型与队长模型的区别**

两者的大框架相同：都是"时域 + 频域两路输入 → 共享 Transformer → 三个任务头"的单一基座，都用固定权重的卷积实现短时谱，都按 RMS 归一化、按长度分桶。区别在下面几处，其中前三处是实质性的。

| 方面 | 队长模型（`leader/code/models/rf_model.py`） | 自研模型（第 4 节 + 4.12 节修订） | 预期影响 |
|---|---|---|---|
| **时域前端** | 一层核 5 的卷积，然后一步 16 点分块（步长 16 的卷积） | 步长 2 的卷积两次到 L/4，再经三个卷积阶段逐步降到 L/16 | 自研保留了 4 倍下采样处的细时间结构，脉冲边沿位置不会在第一步就被抹平。主要影响 `pulse_width`、`pri`、`time_delay` |
| **主干构成** | 分块后全部是 Transformer（8 或 12 层），计算集中在注意力 | 卷积阶段为主（每路 8 个重参数化卷积块），后接少量 Transformer 层（Base 6 层，Tiny 0–1 层） | 卷积块推理时可合并成单层卷积，小规模下更快，算子更容易移植到国产平台。主要影响复赛时延 |
| **参数头** | 7 个查询向量各自做注意力池化，共用一个回归头输出 7 个连续值；可选"网格期望 + 残差" | 先分脉冲组 / 通信组；(`symbol_rate`, `bandwidth`) 22 类联合分类；`frequency_shift` 三类粗分加小频偏回归；`number_of_pulses` 5 类；三个时间量归一化回归 | 队长的 `symbol_rate`、`bandwidth` MAE 很小而 RMSE 很大，说明误差来自少数严重错分，联合分类针对的正是这一点 |
| 短时谱 | 窗 64、步长 16，每个 token 一帧，谱直接映射到 token 维度 | 窗 64、步长 4，频域单独一路卷积，与时域同步下采样 | 自研的时频分辨率高 4 倍，计算量也更大 |
| 全局谱 | 1024 点全谱直接接两层线性层，结果加到每个 token 上 | 只取中心频带，另加包络谱，沿频率轴卷积后作为一个额外 token | 窄带信号集中在中心频带，包络谱含码元速率谱线。队长的做法对频移不具备平移等变性 |
| 时频融合 | 分块后一次门控相加 | 三个阶段各做一次双向门控，最后拼接合并 | 影响较小，由消融决定 |
| 输入通道 | I、Q、幅度（可选相位差分特征，默认关） | I、Q、包络平方、位置斜坡（差分乘积通道为消融项） | 影响较小 |
| 位置信息 | 旋转位置编码 + 绝对坐标特征 | 位置斜坡通道 + 正弦绝对位置编码 + 长度嵌入 | 队长的旋转位置编码更成熟，可以借鉴 |
| 分类读出 | 所有 token 取平均，两个分类头共用同一个平均向量 | 每个任务一个查询向量做注意力池化 | 影响较小 |
| 归一化 | LayerNorm，注意力 Q/K 归一化 | 卷积部分 BatchNorm（推理时折叠进卷积），Transformer 部分 LayerNorm | 自研的 Transformer 层也要加 Q/K 归一化（队长的教训） |
| 规模 | 17.1M / 95.7M | Base 约 20M / Tiny 约 1M（手算估计，以统计脚本为准） | Base 与队长小模型同量级，便于直接对比 |

需要如实说明的两点：

- 自研模型目前**没有任何实测数字**，上表"预期影响"一列都是推断。队长的模型已经有 61.7%–64.5% 的调制准确率和 93.4%–94.4% 的体制准确率。
- 队长试过的"局部残差卷积前端"没有收益，但那是在分块前加同分辨率卷积，分块本身仍是一步 16 倍，与自研的逐级下采样不同。自研前端是否真的更好，只有首轮训练能回答。

**（九）首轮有监督训练（当前第一目标）**

目的是尽快得到自研模型在同一验证集上的三项指标和代理分，与队长基线并排比较。不做预训练、不做蒸馏、不接 EMind、不做测试时增强。

*模型配置*：Base 档（C=96，D=384，Transformer 6 层），按 4.8 节的逐层规格，并采用 4.12 节的修改 1（包络平方通道必选，差分乘积通道先不加）、修改 2（全局谱支路）、修改 3（参数头）。Transformer 层加 Q/K 归一化。跨任务条件化先不加。训练前打印参数量和共享占比。

*训练配方*（沿用队长验证过的设置，减少变量）：

- 每个 batch 是同一任务、同一长度的记录；三个任务均衡轮转。通信组和脉冲组的参数样本长度不同，自然分在不同 batch。
- 当前 batch 没有用到的任务头，优化器更新前把梯度置为 None。
- AdamW，峰值学习率 3e-4，权重衰减 0.01，线性预热 300–500 步后余弦衰减到峰值的 5%，梯度裁剪 1.0，每卡 batch 256，BF16 混合精度训练、FP32 验证。
- 先跑 30 轮（与队长 17M 模型的计划一致），每轮验证一次，按代理分保存最优权重。队长的 17M 模型第 5 轮就达到 61.7%，所以前几轮就能看出自研模型的大致水平。
- 首轮不加数据增强。队长试过的相位旋转、循环平移、标签平滑都没有稳定收益。
- 损失：两个分类任务用交叉熵；参数任务为各分类输出的交叉熵加各回归输出的 MSE，只在样本所属子群上计算，各项先取平均再相加，三个任务的损失权重都取 1。
- 用一对 GPU（0/1、2/3 或 4/5，与队长错开），多卡时设置 `NCCL_CUMEM_HOST_ENABLE=0`。

*开跑前的三项检查*（各几分钟，能避免白跑一整轮）：

1. 划分行数与队长一致（见本节一）。
2. 在 256 条样本上过拟合：训练准确率应能接近 100%，三个时间量的训练误差应降到很小。做不到说明数据管线或损失有错。
3. 重参数化融合前后输出一致（最大绝对误差小于 1e-4）；512 和 1024 两种长度都能前向。

*汇报内容*：参数量与共享占比；每轮的训练和验证曲线；最优轮次的调制准确率（另分"14 个窄带类"和"其余 9 类"）、体制准确率、七个参数各自的 RMSE 与 MAE、代理分；与本节（三）的队长基线并排成表；单卡吞吐（条/秒）。

*如何解读结果*：

- 三个脉冲时间量的 RMSE 明显低于队长的 0.98 / 0.74 / 1.10 µs：细时间分辨率前端有效，这是自研模型的主要卖点。
- `symbol_rate`、`bandwidth` 的 RMSE 明显低于队长的 202.6 / 270.3：联合分类参数头有效。这个头可以直接建议队长也采用。
- 调制准确率与队长接近（约 62%–64%）属于预期：14 个窄带类的瓶颈在信息量，不在结构。明显更低则先查全局谱支路和训练是否收敛。
- 体制准确率应在 93% 以上，明显更低说明实现有问题。
- 验证指标早早停止上升而训练指标继续上升，是过拟合，记录最优轮次即可，首轮不调参。

首轮结果出来之后，再按本节（七）的顺序做对照实验。

## 2. 得分结构分析与总体战略

这一节决定了所有后续取舍，务必理解。

**初赛只比精度，参数估计权重最大（40 分）。** 120 万条样本上，两个分类任务在高信噪比段大概率接近饱和，各队差距主要来自低信噪比样本和参数估计。所以初赛的主要精力应放在参数估计上（第 6 节）。

**复赛时延排名的权重远超精度。** 效率分每前进一名值 `30 / (N−1)` 分（自动评分口径）。举例：

| 复赛队伍数 N | 时延每前进一名 | 相当于单个分类任务的准确率 |
|---|---|---|
| 10 | 3.33 分 | 16.7 个百分点 |
| 20 | 1.58 分 | 7.9 个百分点 |
| 30 | 1.03 分 | 5.2 个百分点 |

也就是说，复赛里用 1 个百分点的准确率换一名时延排名是非常划算的。**不要提交大模型去复赛。**

由此得出两阶段战略：

1. **初赛：做一个中等规模的高精度模型**（约 15–30M 参数，记为 `Base`），目标是精度最大化以确保晋级。
2. **复赛：把 `Base` 蒸馏到同架构族的极小模型**（约 1–3M 参数，记为 `Tiny`），配合结构重参数化、BN 融合、半精度和 I/O 优化，争取时延第一梯队，同时把精度损失控制在 1 个百分点以内。
3. **专家评审（复赛 30%）**：架构设计要逐条对应赛题的三项任务描述（时频双流融合、多任务统一表征、国产化迁移），并用消融实验证明每个设计有效。第 4 节的架构就是按这个要求组织的。

关于"拿开源大模型微调"：通用的时序或音频大模型不考虑，理由是模态不匹配。但文献调研发现了一个电磁信号专用的开源基础模型 EMind，其预训练数据与本赛题高度相关，所以它作为并行的第二条路线保留（见 4.11 节）。不论初赛用哪条路线，复赛提交的都应是蒸馏后的小模型。

## 4. 模型架构：时频双流统一基座（暂名 TF-UniEM）

### 4.1 总览

```
IQ (2×L)
  ├─ 时域流：卷积干 → 多尺度卷积块 ─┐
  │                                 ├─ 每个阶段末尾：跨域门控融合（双向）
  └─ 频域流：卷积化 STFT → 卷积块 ──┘
            ↓ 三个阶段后合并（拼接 + 1×1 卷积）
        共享 Transformer 编码层（序列长度 L/16，即 32 或 64 个 token）
            ↓
        任务查询注意力池化（3 个可学习任务查询向量）
            ↓
   体制头(8)    调制头(23)    参数头(7)
```

共享部分 = 双流编码器 + 融合模块 + Transformer 层；任务专属部分 = 任务查询向量 + 三个小 MLP 头。设计目标是共享参数占比 ≥ 95%，远高于 80% 的红线。

### 4.2 输入预处理

- 每条样本按 RMS 功率归一化；把归一化前的 `log(RMS)` 作为一个标量特征送入池化后的表征（幅度可能与某些参数相关，EDA 后决定去留）。
- 512 和 1024 两种长度**不要补零到同一长度**，按长度分桶组 batch。模型全卷积加全局池化，天然支持两种长度。

### 4.3 时域流

- 输入通道：I、Q，外加 `I² + Q²`（包络平方）。包络平方的频谱里含码元速率谱线，是码元速率估计的经典特征，显式给出比让网络自己学更稳。是否保留由消融决定。
- 再加一个**位置通道**：`n / 1024` 的线性斜坡（n 为采样点序号）。7 个参数里有 `time_delay`，它依赖信号在窗口中的绝对位置，而卷积加全局池化对平移近似不变，不给位置信息就估不准。
- 卷积干：`Conv1d(k=7, s=2)` → `Conv1d(k=3, s=2)`，输出长度 L/4，通道数 C。
- 三个阶段，分辨率 L/4 → L/8 → L/16，通道 C → 2C → 4C。每个阶段若干个大核（k=7）卷积块，训练时用多分支（k=7、k=3、恒等），推理时重参数化为单个卷积（RepVGG 思路）。

### 4.4 频域流：卷积化 STFT

**不要用 `torch.stft` 或复数张量**，国产平台和 ONNX 对它们支持差。改用一个固定初始化的 `Conv1d` 实现 STFT：

- `Conv1d(in=2, out=2K, kernel=N, stride=hop, bias=False)`，取 N=64、K=64、hop=4、padding=30，输出帧数恰为 L/4，与时域流逐帧对齐。
- 设 `θ = 2πkn/N`，`w[n]` 为 Hann 窗，k 取 −K/2 … K/2−1（复信号要双边谱）：
  - 实部核：I 通道权重 `w·cos θ`，Q 通道权重 `w·sin θ`
  - 虚部核：I 通道权重 `−w·sin θ`，Q 通道权重 `w·cos θ`
- 之后算 `log(Re² + Im² + ε)` 得对数功率谱，把 K 个频点当作通道，接 `Conv1d` 映射到 C 维，再走与时域流同构的三个阶段。
- 卷积核以 DFT 基初始化后是否放开微调（即可学习滤波器组），由消融决定。

这样整个模型只含 Conv1d、Linear、BN/LN、加乘、矩阵乘、Softmax、log 等基础算子。

### 4.5 跨域融合

每个阶段末尾做一次双向跨域门控：用一个流的全局统计（时间维均值 → 小 MLP → Sigmoid）生成通道门控，调制另一个流，反之亦然。计算量很小。第三阶段后把两流拼接，经 1×1 卷积合并，送入 Transformer 层做注意力层面的融合。

这对应赛题任务 1 所说的"通道、空间或注意力层面的动态对齐与融合"：时间对齐由 STFT 的 hop 设计保证，通道层面是门控，注意力层面是后面的 Transformer。

### 4.6 多任务适配

- **任务查询池化**：3 个可学习查询向量，各自对 Transformer 输出的 token 序列做一次注意力池化，得到任务专属表征。参数极少，却让三个任务各取所需。
- **跨任务条件化**：把体制头和调制头的输出概率（截断梯度）拼到参数头的输入里。物理上合理：脉冲宽度只对雷达类有意义，码元速率的分布依赖调制方式。这对应赛题任务 2 的"挖掘任务间潜在关联、协同增效"，必须用消融验证它确实涨分。
- 推理时按样本的 `task` 字段只计算需要的那个头。

### 4.7 规模档位

| 档位 | 用途 | C | Transformer 层数 | 参数量目标 |
|---|---|---|---|---|
| Base | 初赛、蒸馏教师 | 64–96 | 4–6 | 约 15–30M |
| Tiny | 复赛提交 | 24–32 | 0–2 | 约 1–3M |

以上是目标区间，实际数字由脚本统计。Tiny 可以尝试完全去掉 Transformer 层（纯卷积最快，算子也最好移植），由精度-时延曲线决定。

### 4.8 逐层规格

记 B 为 batch，L 为 512 或 1024，C 为基础通道数，D 为合并后的维度。下表以 Base（C=96，D=384）为例，括号内为 Tiny（C=32，D=128）。

| 步骤 | 模块 | 输出形状 |
|---|---|---|
| 0 | 输入 `iq`，转成 (B, 2, L) | (B, 2, L) |
| 1 | RMS 归一化：`rms = sqrt(mean(I²+Q²))`，`x = x / rms`，记 `s = log(rms)` | (B, 2, L)，s: (B, 1) |
| 2a | 时域输入拼接：I、Q、I²+Q²、位置斜坡 | (B, 4, L) |
| 3a | 时域干：Conv(4→C/2, k7, s2) + BN + GELU；Conv(C/2→C, k3, s2) + BN + GELU | (B, C, L/4) |
| 2b | 频域：ConvSTFT(N=64, hop=4, pad=30) → 对数功率谱 | (B, 64, L/4) |
| 3b | 频域干：Conv(64→C, k3) + BN + GELU | (B, C, L/4) |
| 4 | 阶段 1：两流各 2（1）个 RepBlock(C)；末尾跨域门控 | 两流各 (B, C, L/4) |
| 5 | 下采样：两流各 Conv(C→2C, k3, s2) + BN | (B, 2C, L/8) |
| 6 | 阶段 2：两流各 2（1）个 RepBlock(2C)；末尾跨域门控 | 两流各 (B, 2C, L/8) |
| 7 | 下采样：两流各 Conv(2C→4C, k3, s2) + BN | (B, 4C, L/16) |
| 7b | 高分辨率频谱：ConvSTFT(N=256, hop=16, pad=120) → 对数功率谱 → Conv(256→4C, k3) + BN + GELU，与频域流相加 | (B, 4C, L/16) |
| 8 | 阶段 3：两流各 4（2）个 RepBlock(4C)；末尾跨域门控 | 两流各 (B, 4C, L/16) |
| 9 | 合并：通道拼接 → Conv(8C→D, k1) + BN + GELU | (B, D, L/16) |
| 10 | 转成 token 序列，加正弦绝对位置编码（按 token 序号，两种长度共用同一张表的前 32/64 行） | (B, L/16, D) |
| 11 | Transformer 编码层 ×6（×0–1）：Pre-LN，6（4）头，MLP 扩张比 4（2） | (B, L/16, D) |
| 12 | 任务查询池化：按样本的任务取对应查询向量，对 token 做单头注意力加权求和 | (B, D) |
| 13 | 加上长度嵌入（2 项：512 / 1024），拼接 `s` | (B, D+1) |
| 14 | 任务头（见下） | 8 / 23 / 7 |

各模块定义：

- **RepBlock(d)**，训练时三个并联分支求和后过激活：`Conv(d→d, k7) + BN`、`Conv(d→d, k3) + BN`、`BN`（恒等分支）。推理前融合：每个分支先把 BN 折进卷积（`w' = w·γ/σ`，`b' = β − μ·γ/σ`），k3 的核两侧各补 2 个零变成 k7，恒等分支写成中心为 1 的 k7 核，三者相加得到单个 `Conv(d→d, k7)`。融合前后输出的最大绝对误差应小于 1e-4，写成单元测试。
- **跨域门控 CDG(d)**：`g_F→T = Sigmoid(Linear(d/4→d)(ReLU(Linear(d→d/4)(mean_t(F)))))`，`T ← T · g_F→T`；对称地用 T 的统计门控 F。两个方向各有独立参数。
- **任务查询池化**：3 个可学习向量 `q_k ∈ R^D`。`a = Softmax(K(tokens) · q_k / sqrt(D))`，`z = Σ a_i · V(tokens_i)`，其中 K、V 是两个共享的 Linear(D→D)。
- **分类头**（体制、调制各一个）：LayerNorm → Linear(D+1→D/2) → GELU → Linear(D/2→类别数)。
- **参数头**（按 1.4 节的实测结论设计）：共享一段躯干 LayerNorm → Linear(→D) → GELU → Linear(D→D/2) → GELU，之后分出 8 个线性输出：
  - 子群分类（2 类：脉冲组 / 通信组），用于决定输出哪一组、另一组填 0.0；
  - (`symbol_rate`, `bandwidth`) **联合分类**（22 类，取代两个独立分类头）；
  - `frequency_shift` 拆成两部分：粗分类 3 类（小频偏 / 100 / 1000），外加一个小频偏回归输出（目标为 `frequency_shift / 50`，范围 [−1, 1]，MSE 损失，只在小频偏样本上计算）。最终输出 = P(100)×100 + P(1000)×1000 + P(小频偏)×回归值×50，或取最大概率分支，两者在验证集上比 RMSE；
  - `number_of_pulses` 分类（5 档：2–6）；
  - `pulse_width`、`pri`、`time_delay` 各 1 个回归输出，目标线性归一化到 [0, 1]（分别对应 10–16 µs、17–23 µs、1–10 µs），推理时反归一化并裁剪到训练范围。
  - 档位表和归一化范围从训练集统计得到，存进 `weights/config.json`，不要写死在代码里。
  - 分类型参数的最终输出有两种取法：取概率最大的档位，或取概率加权的期望值。逐参数在验证集上比较 RMSE，取低者。
  - 损失只在样本所属子群的输出上计算；子群分类头对所有参数样本计算。
- **跨任务条件化**改为消融项 A8：把截断梯度的体制、调制概率拼到参数头输入。实测数据里参数样本的子群靠信号本身就能区分，这一设计未必有增益，有提升才保留。

参数量粗估（Base）：阶段 3 的 8 个 RepBlock 融合后约 8M，Transformer 6 层约 10.6M，其余约 2M，合计约 20M；三个任务头加查询向量约 0.3–0.5M，共享占比约 98%。Tiny 约 1M。这些是手算估计，以 `count_params.py` 的输出为准。

### 4.9 关键模块参考实现

ConvSTFT 的初始化最容易写错，直接给出：

```python
import math, torch, torch.nn as nn

class ConvSTFT(nn.Module):
    """用固定初始化的 Conv1d 实现复信号的双边 STFT，输出对数功率谱。"""
    def __init__(self, n_fft=64, hop=4, learnable=False):
        super().__init__()
        n = torch.arange(n_fft, dtype=torch.float32)
        k = torch.arange(-n_fft // 2, n_fft // 2, dtype=torch.float32)
        theta = 2 * math.pi * k[:, None] * n[None, :] / n_fft      # (K, N)
        win = torch.hann_window(n_fft, periodic=True)
        cos, sin = torch.cos(theta) * win, torch.sin(theta) * win
        re = torch.stack([cos, sin], dim=1)    # (K, 2, N): I*cos + Q*sin
        im = torch.stack([-sin, cos], dim=1)   # (K, 2, N): Q*cos - I*sin
        self.conv = nn.Conv1d(2, 2 * n_fft, n_fft, stride=hop,
                              padding=(n_fft - hop) // 2, bias=False)
        self.conv.weight.data.copy_(torch.cat([re, im], dim=0))
        self.conv.weight.requires_grad_(learnable)
        self.k = n_fft

    def forward(self, x):                      # x: (B, 2, L)
        y = self.conv(x)
        power = y[:, :self.k] ** 2 + y[:, self.k:] ** 2
        return torch.log(power + 1e-6)         # (B, K, L / hop)
```

必须写一个单元测试：对随机复信号，把本模块的功率谱与 `torch.stft`（同窗、同 hop、`center=False`，自行对齐补零和 `fftshift`）的结果比较，确认一致后再用。

### 4.10 为什么不用开源大模型微调（以及何时改变主意）

1. **没有合适的预训练模型。** 主流开源基础模型是在文本、图像、语音或通用时间序列上预训练的，输入是 512/1024 点复基带 IQ 时，模态不匹配，预训练知识能迁移多少没有保证。
2. **数据量足够从零训练。** 120 万条有标签样本、封闭集 8 类加 23 类加 7 个回归量，这个规模的任务用千万级参数的专用网络通常就能训练充分。
3. **时延排名占复赛自动评分 30 分**，大模型在这一项上天然吃亏（见第 2 节）。
4. **国产平台算子适配**：自己设计的网络可以把算子限制在白名单里，大模型做不到。
5. **专家评审的创新性占 20 分**：自研的时频双流结构比"某开源模型加 LoRA"有更多可讲的内容。

**以上第 1 条已被文献调研修正**：存在电磁信号专用的开源基础模型 EMind，且与本赛题数据高度相关（见 4.11 节）。第 2–5 条仍然成立，但它们只说明"复赛不能直接提交大模型"，不能说明"初赛和蒸馏教师不该用它"。所以现在的做法是双轨并行（第 10 节 A13）：EMind 微调与自研 Base 在同一验证集上比较，初赛提交分数高者，并以它作为蒸馏教师；复赛提交仍用 Tiny。另外，赛题原文有"在开源基础模型上……开展基座模型构建"的表述，同时又写明"可以设计新的网络架构从零构建"，从零构建是允许的，但建议用户向组委会确认一次。

**据此的修订**

1. **路线从"只做自研"改为"双轨并行、用验证集决定"**：
   - 轨道 A：自研 TF-UniEM（4.1–4.9 节）。
   - 轨道 B：下载 EMind 预训练权重，接上同样的任务头，全量微调。
   - 两者在同一验证集上比加权总分。初赛提交分数高者；无论谁高，复赛都蒸馏到 Tiny。如果 EMind 明显更强，它是更好的教师，而且"在开源电磁基础模型上构建并蒸馏压缩"的叙事与赛题原文更贴合。
   - EMind 的 patch 大小为 8，对脉冲组需要的亚采样点时间精度可能不利，这一点用实验验证，不要预设结论。
2. **自监督预训练从次优先级升为主线实验**：对 TF-UniEM 做掩码重建预训练（时域 patch 掩码，重建 IQ 和对数谱，掩码率从 60%–75% 起试），与纯监督对比。
3. **回归损失多试一种**：RadChar 原文用 L1。本赛题指标是 RMSE，理论上 MSE 更对口，但 L1/Huber 在低信噪比下更稳，三者在验证集上比 RMSE。
4. **按信噪比分段评估**：脉冲组信噪比范围很宽，验证时用包络信噪比估计把样本分段，分别看误差。低信噪比段模型应输出接近条件均值的保守估计，MSE 训练天然具备这一性质。
5. **不采用**：SpectrumFM 的幅度-相位输入（需要 `atan2`，不利于国产平台算子适配，且本方案的时频双流已覆盖相位信息）。

**需要用户决定或向组委会确认的三件事**

- **EMind 的使用许可**：代码和权重都没有许可证声明。在比赛中使用前，建议向组委会确认它是否属于允许的"开源基础模型"。
- **是否允许使用公开的 RadChar 数据做额外训练**：RadChar 有 100 万条公开样本。但若测试集与它同源甚至重叠，使用它有成绩被判无效的风险。**默认不用**，除非组委会明确允许，且在 `datasets/readme.txt` 中如实申报。
- EMind 预训练时用过的数据可能与本赛题测试集同源。使用其权重是否合规，同样以组委会答复为准。

### 4.12 结合文献与两轮数据核实后，对自研模型的修订

结论：**主干的整体形态不用推翻，但输入特征、频域支路和参数头需要改**。改动的依据主要来自数据（1.4、1.5 节），文献（4.11 节）提供的是方向上的佐证。以下各条覆盖 4.2–4.8 节中与之冲突的内容。

**保留不变的部分**

- 时域流早期只做 4 倍下采样。脉冲参数换算后需要亚采样点精度；EMind 用的 patch 大小是 8，在这一点上自研结构反而更合适，用实验验证。
- 卷积阶段在前、少量 Transformer 层在后的混合结构。SpectrumFM 等工作采用的也是卷积与注意力混合。
- 重参数化卷积、任务查询池化、Base 与 Tiny 两档、蒸馏流程。

**修改 1：输入通道**（原为 I、Q、包络平方、位置）

- **包络平方通道从消融项改为必选**。脉冲组一半样本的脉冲淹没在噪声里，先取 `I²+Q²` 再用大核卷积做时间平均，等价于非相干积累，是低信噪比下估计脉冲时序的基础；它的谱线还直接给出码元速率。
- **新增一组差分乘积通道**（消融项）：`d_k[n] = x[n] · conj(x[n−k])` 的实部和虚部，k 取 1 和 8，共 4 个通道。载频偏移在这组通道里变成一个固定的相位旋转，不再是随时间累积的旋转，有助于窄带调制类在 100/1000 kHz 频偏下的识别。只涉及乘法和加减，不引入 `atan2`。
- 长度嵌入同时起到"采样率标识"的作用（512 点对应约 3.2 MHz，1024 点对应 20 MHz），与 EMind 的采样率 token 思路一致。

**修改 2：频域流改为"局部谱 + 全局谱"两级**

原方案的 64 点 STFT 分辨率是 1/64 周期/采样点，而窄带信号全部落在 ±0.05 以内，码元速率谱线在 0.005–0.05，频偏的区分需要 0.001 量级的分辨率。64 点和 256 点的 STFT 都不够，取消 4.8 节的步骤 7b，改为：

- **局部谱**（保留）：ConvSTFT(N=64, hop=4)，服务于宽带信号、雷达脉内调制和时频对齐融合。
- **全局谱支路**（新增）：对整段信号做一次全长变换，用固定权重的 `Conv1d(kernel=L, stride=L)` 实现，512 和 1024 各一份。输出两条谱：
  - 信号谱：`log|DFT(x)|²`，1024 点时只取中心 256 个频点（|f| < 0.125），512 点时取全部或中心 256 个；
  - 包络谱：`log|DFT(|x|² − 均值)|²`，取第 1 到第 128 个频点。
  - 两条谱各自减去均值后，沿频率轴过 3 层 `Conv1d(k=5, s=2)` + BN + GELU，全局平均池化与最大池化拼接，经 Linear 映射到 D 维，作为一个额外 token 拼进 Transformer 输入序列；Tiny 没有 Transformer 层时改为加到池化后的表征上。
  - 固定的变换核不训练，可在加载时生成而不存入权重文件；若存入，计入共享参数。
- 对 Tiny 而言这条支路性价比最高：计算量很小，却把码元速率、频偏、带宽这些量直接摆在了特征里。

**修改 3：参数头按实测结构重排**（已同步改入 4.8 节）

- (`symbol_rate`, `bandwidth`) 22 类联合分类。
- `frequency_shift`：3 类粗分类加小频偏回归。那 11 个小频偏档位无法逐档分辨，按连续量回归、输出条件均值是 RMSE 意义下的最优做法。
- **跨任务条件化（A8）现在有了明确依据**：同一码元速率下的带宽差异很可能由调制方式决定，所以把调制头的概率（截断梯度）送进参数头是合理的。反过来，参数任务的 `bandwidth / symbol_rate` 比值也是一个粗粒度的调制族标签，共享主干会让调制任务从这 41.4 万条样本中受益。

**修改 4：训练与评估**

- 脉冲组三个回归量：验证时按包络信噪比分段报告误差。低信噪比段的预测应当向均值收缩，这是 MSE 训练下的正确行为，不要为了"看起来准"去修正它。
- 调制任务：把 14 个窄带类和 9 个仿真类分开统计准确率，分别看混淆矩阵。前者的上限由信息量决定，后者由信噪比决定，改进手段不同。
- 增强：对窄带调制类可以试"整体载频旋转"增强（乘以 `exp(j2πf₀n)`，f₀ 在训练分布的两个频偏附近小范围抖动）；对参数任务仍然禁用。

**对规模判断的影响**

三个任务的主要失分点分别是信息量上限（码元太少）和低信噪比，都不是靠加大模型能解决的。这支持"小模型也能接近上限"的判断，对复赛的时延策略有利。但这是推断，以 Base、Tiny、EMind 三者在验证集上的实测差距为准。

## 5. 训练方案

### 5.1 数据管线

- 一次性把 Parquet 转成 numpy memmap（`float16` 或原始整型），按长度分成 512 与 1024 两个数组；标签另存。120 万 × 2 × 1024 的 float32 约 10 GB，float16 减半。
- 验证集：每个任务按类别（回归按参数分箱）分层抽 5%，固定随机种子，全程不变。先检查是否有重复样本，避免训练/验证泄漏。
- 第一周就写好 `utils/score.py`，严格复现 1.3 节的公式，输出三项得分和加权总分，以及按类别、按参数的明细。

### 5.2 多任务训练

- 混合 batch：每个 batch 内三类任务的样本都有，损失只在样本所属任务的头上计算（掩码）。
- 损失权重初始按 0.3 / 0.3 / 0.4；再试不确定性加权，取验证集加权总分高者。
- 分类：交叉熵 + 标签平滑 0.1。若类别不均衡明显，试类别均衡采样（平局时比宏平均召回率）。
- 回归：见第 6 节。
- 优化：AdamW，学习率 1e-3 起试，权重衰减 0.05，warmup + 余弦退火，混合精度，权重 EMA（最终提交 EMA 权重）。batch 512–2048，按显存定。
- 先用 10% 数据跑通全流程并得到一个基线分数，再放全量。
- **算力用法**：服务器有 6 张 A100。模型很小，单卡就能训练，所以优先"一卡一个实验"并行跑消融，而不是 6 卡合训一个模型。只有 Base 的最终长训练和 A13 的大模型对照才需要多卡（DDP）。

### 5.3 数据增强：按任务设白名单

增强必须**不改变标签**。参数估计任务尤其危险，下面的判断要在确认 U3 之后逐条核对：

| 增强 | 分类任务 | 参数估计任务 |
|---|---|---|
| 随机整体相位旋转 | 安全 | 安全 |
| 幅度缩放（归一化后基本无效） | 安全 | 安全 |
| 时间平移/裁剪 | 一般安全 | 脉冲组**不安全**：改变 `time_delay`，裁剪还可能改变 `number_of_pulses`。通信组的三个参数不受影响，可用 |
| 加噪声 | 一般安全 | 7 个参数里没有信噪比，原则上可用，需消融验证 |
| 频偏 | 需验证 | **不安全**：改变 `frequency_shift`。只有在确认采样率和单位后同步修正标签才可用 |
| 共轭 | 可能改变类别（如上/下调频） | 使 `frequency_shift` 变号，需同步把标签取负 |
| 时间反转 | 可能改变类别 | 改变 `time_delay`，禁用 |
| 重采样 | 可能改变体制特征 | 改变 `symbol_rate`、`bandwidth`、`pulse_width`、`pri`，禁用 |

因为混合 batch 里三类任务的样本都有，增强要**按样本的任务分别施加**，不能整个 batch 用同一套。

每种增强单独做消融，没有提升就不用。

### 5.4 自监督预训练（主线实验）

掩码信号建模：随机遮挡时域 patch，重建被遮挡的 IQ 和对应的对数谱。文献调研显示这是电磁/无线基础模型最主流的预训练方式（见 4.11 节），所以它是必做的对比实验。在 120 万条全部有标签的情况下，精度增益可能有限，这一点如实评估。做法：先跑通纯监督多任务基线，随后做预训练并对比；有提升就并入，没有提升也把对比结果写进技术报告。**预训练只用训练集，不要用测试集数据。**

### 5.5 蒸馏（复赛）

Base 做教师，Tiny 做学生：分类用软标签 KL（温度 2–4）加硬标签交叉熵，回归用教师输出与真值的混合目标，可加池化后特征的对齐损失。最终提交的只有 Tiny 一个模型。在技术报告中如实写明蒸馏流程。

### 5.6 测试时增强

对同一模型做多次相位旋转后取平均，不属于多模型集成，但处于规则的灰色地带，且会成倍增加时延。只在初赛、且验证集上确有提升时考虑；用之前请用户决定是否采用，复赛不用。

## 6. 参数估计专项（初赛 40 分，最值得投入）

1. **逐个参数做 EDA**：取值范围、分布、唯一值个数、与体制/调制类别的关系、哪些样本该参数有效。
2. **损失要对准指标。** 指标是原始量纲的 RMSE 除以参考尺度，所以最优预测是条件均值。做法：把目标除以参考尺度（未知时用标准差）后用 MSE 或 Huber 训练。若为了稳定而在对数域训练，最后必须在线性域用 MSE 微调，否则预测有系统偏差。
3. **无效参数用掩码**：按有效性标识只对有效的参数算损失。
4. **离散取值的参数做分类**。实测已确认 `symbol_rate`（6 档）、`bandwidth`（21 档）、`frequency_shift`（13 档）、`number_of_pulses`（5 档）都是离散的，按 4.8 节的参数头实现。分类正确时误差为零，所以这四个参数的 RMSE 主要由错分决定：错分到相邻档位代价小，把 100 错成 1000 代价大。输出取"最大概率档位"还是"概率期望"，逐参数在验证集上比 RMSE 决定。另外试一个变体：把 `symbol_rate` 与 `bandwidth` 合并成一个联合类别来分类（若交叉表显示两者确实联合取值）。
4b. **三个连续参数（`pulse_width`、`pri`、`time_delay`）是真正的回归问题**，也是参数任务里最可能拉开差距的地方。它们换算成采样点后需要亚采样点精度，所以时域流在 L/4 之前不要过度下采样，位置通道和位置编码必须保留。可以试一个辅助监督：让模型在 token 级别预测"此处是否在脉冲内"的掩码（由 `time_delay`、`pri`、`pulse_width`、`number_of_pulses` 四个标签直接生成，前提是先核实这四个量与波形的对应关系），作为消融项。
5. **预测值裁剪**到训练集的取值范围内。RMSE 对离群预测极其敏感，这一步几乎零成本。
6. **多分辨率频谱**：N=64 的 STFT 频率分辨率有限，带宽、码元速率这类参数可能需要更细的谱。消融项：增加一路 N=256 的 STFT，或加一个整段 FFT 对数谱的全局支路。
7. 按参数、按信噪比段（若能估计）输出误差明细，找出拉低总分的那一两个参数，集中优化。
8. **7 个参数的物理分组**（EDA 时验证）：`symbol_rate`、`bandwidth`、`frequency_shift` 偏频域，主要靠频域流；`pulse_width`、`pri`、`time_delay`、`number_of_pulses` 偏时域包络结构，主要靠时域流和位置信息。`number_of_pulses` 是计数量，`pulse_width`、`pri` 多半只对脉冲类信号有效。
9. **不适用的参数输出 `0.0`**，与官方样例的期望输出一致。适用哪一组由参数头的子群分类决定。绝不能输出 NaN、Inf 或缺键。
10. **目标归一化按参数单独做**：各参数量纲相差约 9 个数量级，必须逐参数除以各自的尺度后再算损失，否则大量纲参数会淹没其余参数。

## 7. 效率与国产化（复赛 30 分 + 任务 3）

### 7.1 模型侧

- 结构重参数化：多分支卷积合并为单卷积；BN 融合进卷积。
- 半精度推理（FP16），验证精度无损。
- 两种长度各一个静态形状的计算图，不补零。
- 画出精度-时延曲线（不同 C、不同层数、有无 Transformer），选拐点处的配置。

### 7.2 推理管线侧

模型很小之后，时延大头往往是读写和 Python 开销。具体取决于 U8，但以下各项都要做：

- 用 pyarrow 读 Parquet，`iq` 列向量化转成 numpy，禁止逐样本 Python 循环。
- 按长度分桶，大 batch，一次性搬到设备上。
- 减少启动耗时：只 import 必需的库；权重用 safetensors 直接加载；不要在推理时触发耗时的即时编译，除非实测总时延更低。
- 结果向量化写出，保持 `sample_id` 与输入一一对应。
- 在 `logs/inference.log` 里分段记录耗时（加载、读数据、前向、写出）。

### 7.3 国产平台适配

平台未定（U9），先做与平台无关的准备：

- **算子白名单**：只用 Conv1d、Linear、BatchNorm/LayerNorm、ReLU/GELU/Hardswish、加、乘、矩阵乘、Softmax、均值、log。不用 `torch.fft`/`torch.stft`、复数类型、`einsum`、`atan2`、数据相关的控制流。
- **设备抽象层**：`infer.py` 自动探测后端，顺序为国产加速卡（如昇腾 `torch_npu`）→ CUDA → CPU，任何一个都能跑通并给出一致结果。
- **导出 ONNX**（512、1024 各一个静态图），用 onnxruntime 在 CPU 上校验与 PyTorch 输出一致。ONNX 是通往各家国产工具链的通用中间格式（例如昇腾的 ATC 转 OM）。
- 确认平台后：完成转换，记录 PyTorch-GPU、国产平台两侧的精度与时延对比，写入技术报告和 `logs/`。

官方说明文档（PDF）中与交付直接相关、容易忽略的几条：

- **评测方式**：测试集不向参赛队开放。评测程序读取提交的模型代码和权重，加载测试集运行，返回指标和必要的异常提示。也就是说 `infer.py` 是在主办方环境里被调用的，拿不到中间结果来调试，所以本地必须用官方样例输入输出（`rf_signal_sample_io_v1.0`）做端到端回归测试。
- **复测**：初赛、复赛的最终成绩都"结合成果复测情况"得出，评测过程会追溯重复评测间的结果变化。因此推理必须**确定性可复现**：同一输入多次运行输出完全一致；不使用任何随机操作；固定线程数和算法选择（如 `torch.backends.cudnn.deterministic`）；若用 FP16，确认多次运行结果逐字节一致。
- **复核接口**：主办方"能够以 Python 接口的形式对提交模型权重、训练代码等进行复核"。所以 `infer.py` 除了命令行入口，还要提供可被 import 调用的函数（例如 `load_model(weights_dir)` 和 `predict(input_parquet, output_jsonl)`）；训练代码要能从头复现最终权重（固定随机种子、完整记录超参、`train.log` 保留全过程）。若用了蒸馏，教师模型的训练代码和日志也要包含在内。
- **训练数据来源说明**：交付物要求包含"训练数据及训练数据来源说明"。本方案只使用官方下发的训练集，在 `datasets/readme.txt` 中写明这一点；不要引入外部数据，除非用户同意并如实申报来源。
- **调用方式未定**：文档只说"评测程序直接调用 `infer.py`"，没有给出参数约定。在得到官方答复前，`infer.py` 同时支持位置参数和 `--input` / `--output` 两种写法，并在 README 中写清楚。

提交前自检清单：

- [ ] 用官方样例输入跑 `infer.py`，输出的行数、字段、类别字符串与 `rf_signal_sample_io_expected_output_v1.0.jsonl` 的格式一致。
- [ ] 同一输入连续运行两次，输出文件逐字节相同。

- [ ] `utils/count_params.py` 输出总参数量（< 1B）和共享占比（> 80%），结果写入自测报告。共享占比按两种口径都算：共享参数 / 总参数；以及每个任务前向实际用到的参数中共享部分的占比。
- [ ] 镜像在**断网**状态下（`docker run --network none`）能完整跑通推理。
- [ ] Dockerfile 中没有 `VOLUME` 指令；镜像为 linux 架构。
- [ ] 在干净环境中按 README 从头复现一次推理，输出与本地一致。
- [ ] 所有文件 UTF-8，路径无中文、空格、特殊字符。
- [ ] 输出为 JSONL，每行一个 JSON 对象，行数与输入记录数相等，`task` 和 `sample_id` 原样回填。
- [ ] 分类标签字符串与训练集标签逐字符一致（大小写和空格错了就是错）；类别名到索引的映射表存进 `weights/config.json`。
- [ ] 参数任务每行输出全部 7 个键，值为有限浮点数、原始单位。数值用 Python 默认的浮点表示写出（如 `json.dumps`），**不要用固定小数位格式化**：脉宽是 1e-6 量级，`%.4f` 会把它写成 0。
- [ ] 模型内部若用 FP16，反归一化要在 FP32/FP64 下做，避免小量纲参数丢精度。

**M4 初赛提交包**

## 11. 风险与注意事项

- **标签泄漏式增强**：见 5.3 节，是参数估计最常见的无声失分点。
- **对数域回归不回到线性域**：RMSE 会明显偏高。
- **补零统一长度**：既浪费时延，又可能让模型学到"长度"这个捷径特征。
- **验证集过拟合**：反复调参后，验证集分数会偏乐观。保留一份从不参与调参的小测试集，只在里程碑节点评一次。
- **512/1024 长度与标签相关**：若 EDA 发现强相关，说明存在数据捷径，测试集未必保持，汇报给用户。
- **蒸馏、测试时增强与规则的关系**：蒸馏后只提交一个模型，符合"不集成"的字面要求，但建议用户向组委会确认；测试时增强同理。
- **不要使用测试集做任何训练**（包括自监督和伪标签），除非用户确认规则允许。
- **本方案不能保证获奖**：最终排名取决于未知的测试集分布、参考尺度、时延测量方式和对手水平。能做到的是在已知规则下把期望得分最大化，并保证提交物合规。
